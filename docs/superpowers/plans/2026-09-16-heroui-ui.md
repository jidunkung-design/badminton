# HeroUI UI Implementation Plan

**Goal:** Refresh the existing badminton UI using HeroUI, with a clearly labelled interactive preview of weekly attendance, courts, history and individual scores.

**Architecture:** Keep existing Next.js/Supabase authentication, permissions and live mutations. Use HeroUI v3 and Tailwind v4 for shared presentation. A development-only preview uses fictional in-memory data and never calls database mutations. Configurable score targets (11, 21, custom positive integers) are previewed here before a later scoring persistence change.

**Tech Stack:** Next.js 16, React 19, HeroUI v3, Tailwind v4, existing Vitest.

**Spec:** UI/flow approved in the current conversation, with the earlier club spec as background. UI first; no deployment, commits, remote data changes, rating algorithm changes, or scoring-schema migration.

## Tasks

- [x] Install HeroUI/Tailwind and configure PostCSS. Replace the verbose legacy styles with a small shared theme and responsive shell. Redesign magic-link login while retaining its behavior and handling pending/error states.
- [x] Refresh existing group list, group home, members and court pages with HeroUI. Retain all role checks and existing server actions. Provide clear navigation and empty states.
- [x] Add a development-only, visibly labelled preview. Show weekly roster, playable sample courts with configurable target, match history and per-player totals. Update sample totals after sample score entry. No real account or database writes.
- [x] Test preview score validation/aggregation with existing Vitest, then run type check, lint, unit tests and production build. Visually inspect desktop/mobile login and preview with the browser and exercise 11-point/custom scoring.

## Verification boundaries

Authenticated live pages can be build/type checked without inventing credentials. Browser interaction uses only the labelled local preview; no real match is recorded. Existing result persistence/reload limitations and future real score storage must be stated in the handoff.

## Follow-up: per-player rating change

- Added one shared match-result panel showing each player's Elo before/after and signed delta, with one-decimal display rounding. Game points remain separate from Elo.
- Preview replays the fictional match history through existing `eloDelta`, so subsequent results use preceding ratings. Live court takes before/after directly from `finishMatch`.
- Live result and queue now advance only after `recordMatch` success. Failed/uncertain attempts retain the original match ID and winner for retry; simultaneous result changes are blocked. Historical Elo hydration and reload persistence remain unfinished.
- Verified: 40 unit tests, typecheck, scoped lint and production build; preview browser showed all four changes and no overflow at 390px. Authenticated database mutations were not exercised.
