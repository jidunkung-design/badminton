# ระบบจัดการก๊วนแบดมินตัน — Design Spec

วันที่: 2026-08-04
สถานะ: รอ feedback จากเพื่อน (โปรโตไทป์ส่งไปแล้ว) — ค่าที่ยังไม่ยืนยันระบุไว้ในหัวข้อ "ข้อสมมติที่รอยืนยัน"

---

## 1. ที่มา

ของเดิมคือไฟล์ `index.html` ไฟล์เดียว 2,863 บรรทัด เก็บข้อมูลใน localStorage ล้วน
ใช้งานได้จริงแต่ติดเพดาน 3 อย่าง: ข้อมูลอยู่แค่ในเครื่องเดียว, ไม่มีระบบสิทธิ์, และ ELO เพี้ยนเพราะประวัติถูก cap ไว้ที่ 50 แมตช์

เป้าหมายรอบนี้: ย้ายไปเป็นระบบจริงที่เก็บคะแนนถาวร มีอันดับ มีหลายก๊วน และมีสิทธิ์ในก๊วน

## 2. ขอบเขต

| หัวข้อ | ค่า |
|---|---|
| จำนวนก๊วนสูงสุด | 5 ก๊วนทั้งระบบ (เพดานแข็ง บังคับที่ฐานข้อมูล) |
| ผู้เล่นโดยประมาณ | ~125 คน (25 คนต่อก๊วน) |
| บัญชีที่ล็อกอินจริง | ~30 คน |
| ค่าใช้จ่ายเป้าหมาย | 0 บาท (free tier) ประมาณ 25 ปี ที่ 15 MB/ปี |
| ไม่ทำในรอบนี้ | billing, ระบบเชิญข้ามก๊วน, แอปเนทีฟ, แชท |

## 3. Stack

- **Next.js 15 (App Router) บน Vercel** — Hobby tier, ใช้งานส่วนตัวไม่เชิงพาณิชย์
- **Supabase** — Postgres + Auth + Row Level Security
- **Dexie (IndexedDB)** — คิวงานค้างส่งฝั่ง client
- **PWA** — ติดตั้งลงจอโฮมได้ เปิดตอนไม่มีเน็ตได้

เหตุผลที่เลือก Supabase แทนการเขียน auth เอง: กฎสิทธิ์ 4 ข้อของโปรเจกต์นี้แปลงเป็น RLS policy ได้ตรงๆ
ทำให้สิทธิ์ถูกบังคับที่ฐานข้อมูล ไม่ใช่ที่ JavaScript ซึ่งผู้ใช้แก้ได้

**ความเสี่ยงที่ต้องจัดการตั้งแต่วันแรก**
1. Free tier หยุดโปรเจกต์เมื่อไม่มี request 7 วัน → ตั้ง Vercel cron ping สัปดาห์ละครั้ง
2. Free tier ไม่มี point-in-time recovery → ตั้ง `pg_dump` รายคืนไปเก็บที่อื่น **ก่อน** เปิดใช้จริง
3. Free tier ให้ 2 project → ใช้เป็น dev กับ prod ไม่มี staging

## 4. สิทธิ์และบทบาท

### 4.1 สี่ชั้น

| ชั้น | ใคร | ทำอะไรได้ |
|---|---|---|
| `is_super_admin` (flag บน profile) | เจ้าของระบบคนเดียว | สร้างก๊วน (สูงสุด 5), เห็นทุกก๊วน, ย้ายความเป็นหัวก๊วน |
| `owner` — หัวก๊วน | 1 คนต่อก๊วน | แก้ชื่อ/ปิดซีซั่น/ลบก๊วนตัวเอง, ตั้งและถอดแอดมิน + ทุกอย่างที่แอดมินทำได้ |
| `admin` | หลายคนได้ | จัดการสมาชิก, เช็กชื่อ, จัดคิว, บันทึกผล, กรอกเงิน, เผยแพร่สรุป |
| `member` | สมาชิกที่ผูกบัญชีแล้ว | อ่านอย่างเดียว: อันดับ, สถิติตัวเอง, หน้าสรุปเงิน |

ซูเปอร์แอดมินเป็นหัวก๊วนของก๊วนตัวเองได้พร้อมกัน เพราะเป็นคนละชั้นกัน

### 4.2 ผู้เล่นที่ยังไม่มีบัญชี

แถวใน `players` ที่ `user_id IS NULL` — มีสถิติครบ ไม่มีสิทธิ์ใดๆ
หัวก๊วนส่งลิงก์เชิญเพื่อผูก `user_id` เข้าแถวเดิม สถิติเก่าติดมาทั้งหมด
**ห้ามจับคู่ตัวตนจากชื่อที่ซ้ำกันโดยเด็ดขาด** — "บอส" สองก๊วนอาจเป็นคนละคน

### 4.3 กฎที่บังคับระดับฐานข้อมูล

```sql
-- 1. ทั้งระบบมีได้ 5 ก๊วน
create trigger enforce_group_cap before insert on groups
  -- raise exception เมื่อ (select count(*) from groups) >= 5

-- 2. 1 ก๊วนมีหัวก๊วนคนเดียว
create unique index one_owner_per_group
  on group_members (group_id) where role = 'owner';

-- 3. 1 คนเป็นหัวก๊วนได้ก๊วนเดียว
create unique index one_group_per_owner
  on group_members (user_id) where role = 'owner';

-- 4. สร้างก๊วนได้เฉพาะซูเปอร์แอดมิน
create policy groups_insert on groups
  for insert with check (is_super_admin(auth.uid()));
```

กฎ 2 และ 3 เป็น partial unique index ไม่ใช่ trigger — Postgres บังคับตอนเขียนเสมอ race condition ก็ผิดไม่ได้

ทุกตารางที่มี `group_id` ใช้ policy เดียวกัน:
`group_id in (ก๊วนที่ผู้ใช้เป็นสมาชิก) or is_super_admin(auth.uid())`

## 5. Schema

```
profiles          id (=auth.users), display_name, is_super_admin
groups            id, name, created_by, created_at
group_members     group_id, user_id, role            -- owner|admin|member
players           id, group_id, name, skill, user_id?, archived_at?, last_seen_on?
seasons           id, group_id, name, started_at, ended_at?
sessions          id, group_id, season_id, played_on, status
attendance        session_id, player_id              -- เช็กชื่อ
matches           id, session_id, court_no, mode, queue_mode, balance_weight,
                  winner_team?, started_at, ended_at, client_id UNIQUE
match_players     match_id, player_id, team           -- PK(match_id, player_id)
settlements       id, session_id, hours, court_rate, courts, shuttles,
                  price_per_box, total, share_token, published_at?
settlement_shares settlement_id, player_id, share, amount
stock_movements   id, group_id, type, amount, note, balance_after, client_id UNIQUE
```

**กฎถาวรของ schema**

1. `matches` เป็น append-only ไม่มี cap ไม่มีลบ — นี่คือจุดที่แก้บั๊ก ELO เพี้ยนของเดิม
2. **ไม่มีการลบผู้เล่นจริงทั้งระบบ** มีแต่ `archived_at` — `match_players` อ้างถึงผู้เล่นอยู่
3. `queue_mode` และ `balance_weight` เก็บบนแถว match — แก้บั๊กตัวกรองประวัติของเดิมที่กรองไม่ได้เพราะไม่เคยบันทึกโหมด
4. 1 ก๊วนมีซีซั่นที่เปิดอยู่ได้อันเดียว: partial unique index บน `(group_id) where ended_at is null`
5. ผลแมตช์ในก๊วนหนึ่ง **ต้องไม่กระทบเรตของอีกก๊วน** แม้เป็นบัญชีเดียวกัน — ทุก query ที่คำนวณเรตกรองด้วย `group_id` เสมอ

## 6. เครื่องจัดคิว

### 6.1 หลักการ: เลิกคิดเป็นรอบ

ของเดิมสุ่มทั้งรอบพร้อมกัน และต้องจบครบทุกสนามก่อนสุ่มใหม่ ซึ่งไม่เคยเกิดขึ้นจริง
ของใหม่เป็น **คิว + ช่องสนาม** สนามไหนจบก็ดึงคิวลงสนามนั้นได้ทันที

**แยกสองคำถามที่ของเดิมปนกัน**

| คำถาม | ตัดสินด้วย |
|---|---|
| ใครได้ลงคิวถัดไป | ความเป็นธรรม |
| สี่คนนั้นแบ่งข้างยังไง | เรตฝีมือ |

### 6.2 ความเป็นธรรม

```
priority(id) = (เกมสูงสุดวันนี้ - เกมที่เล่นวันนี้) + นาทีที่รอ × 0.08
```

นับ **เกมของวันนี้เท่านั้น** ไม่ใช่เกมสะสมทั้งซีซั่น
ถ้านับสะสม คนที่มาทุกอาทิตย์จะถูกลงโทษให้ได้ลงน้อยลงตลอดกาล

### 6.3 การแบ่งข้าง

สี่คนแบ่งเป็นสองทีมได้ **3 แบบเท่านั้น** คิดครบทุกแบบ ไม่ต้องสุ่ม

```
score = w × (ผลต่างเรตสองฝั่ง / 4) + (1 - w) × ค่าปรับคู่ซ้ำ
```

`w` มาจากสไลเดอร์ "เน้นสมดุล ↔ เวียนคู่ใหม่" ค่าเริ่มต้น 0.5

### 6.4 สี่โหมด

| โหมด | ดูคนที่รออยู่ | การันตีได้ลง | หมายเหตุ |
|---|---|---|---|
| จัดเอง | — | — | หัวก๊วนเลือกเอง 4 คน |
| เวียนเท่ากัน | 4 คนแรก | 4 คน | ไม่เลือกหน้าเลย |
| ผสม | 6 คนแรก | 2 คนแรก | ค่าเริ่มต้น |
| เน้นสมดุล | 8 คนแรก | 1 คนแรก | |

**การันตีได้ลงต้องมีอย่างน้อย 1 คนเสมอ** — ถ้าใช้ความเป็นธรรมแค่คัดตัวเข้ารอบแล้วเลือกจริงด้วยความสมดุลล้วน คนท้ายกลุ่มจะถูกดองซ้ำๆ

**ผลจำลอง 12 คน 2 สนาม 30 แมตช์**

| โหมด | เกมต่างกันมากสุด | เรตสองฝั่งห่างเฉลี่ย |
|---|---|---|
| เวียนเท่ากัน | 0 เกม | 89 แต้ม |
| ผสม | 5 เกม | 38 แต้ม |
| เน้นสมดุล | 5 เกม | 7 แต้ม |

ในชุดตัวเลขนี้ "ผสม" ไม่ชนะโหมดไหนเลย — ถ้า feedback ยืนยัน ตัดเหลือ 3 โหมด

### 6.5 คิว

- ลึก `จำนวนสนาม + 1` แมตช์ ลึกกว่านี้ผลแข่งยังไม่เข้า ระบบจะคำนวณจากข้อมูลเก่า
- คิวขึ้นให้ดูก่อน **หัวก๊วนต้องกดยืนยันถึงจะลงสนาม**
- แก้ได้ก่อนกด: สลับข้าง, ล็อกไม่ให้ระบบคำนวณใหม่, ทิ้ง
- ทิ้งแล้วชุดนั้นจะไม่ถูกเสนอซ้ำ
- ทุกครั้งที่แมตช์จบ คิวที่ไม่ได้ล็อกถูกคำนวณใหม่จากข้อมูลล่าสุด

### 6.6 เรตที่ใช้จับคู่

```
เรต = (n / (n + 8)) × ELO + (8 / (n + 8)) × (700 + มือ × 100)
```

`n` = เกมที่เล่นในซีซั่นนี้ เล่นน้อยยังเชื่อมือที่กรอกไว้ เล่นเกิน 20 เกมแล้วเชื่อผลจริงเป็นหลัก

## 7. อันดับและซีซั่น

### 7.1 คำนวณตอนอ่าน ไม่เก็บสะสม

SQL function `season_standings(season_id)` ไล่ `matches` เรียงตาม `(started_at, id)` แล้วคำนวณ ELO สด (K=32, ฐาน 1000)

เหตุผล: offline ทำให้แมตช์มาถึงเซิร์ฟเวอร์ไม่เรียงเวลา ELO เป็น order-dependent
ถ้าบวกสะสมทีละแมตช์ ผลจะขึ้นกับลำดับที่เน็ตกลับมา ไม่ใช่ลำดับที่เล่นจริง

ต้นทุน: 1 ซีซั่น ~2,500 แมตช์ = หลักสิบ ms ยังไม่ต้อง cache

### 7.2 ระดับมือ

ใช้ระบบที่ก๊วนไทยเรียกกันจริง ไม่ใช่ Bronze/Silver/Gold

| มือ | ตั้งแต่ |
|---|---|
| B | 1140 |
| C | 1090 |
| P | 1040 |
| S | 990 |
| N | ต่ำกว่า 990 |

แถบความคืบหน้าวัดใน **กรอบ 100 แต้มสุดท้ายก่อนเลื่อนมือ** ไม่ใช่วัดจากพื้นของมือนั้น
(ถ้าวัดจากพื้นของมือ N ซึ่งเป็น 0 ทุกคนจะขึ้นแถบเกือบเต็มตั้งแต่เริ่ม)

### 7.3 สี่กระดาน

| กระดาน | เกณฑ์ | เหตุผล |
|---|---|---|
| เรต | เล่นครบ 5 เกม | อันดับหลัก |
| ชนะมากสุด | เล่นครบ 5 เกม | คนเล่นเยอะแต่เรตกลางๆ ยังมีที่ยืน |
| มาบ่อยสุด | ไม่มีเกณฑ์ | คนที่มาทุกอาทิตย์คือคนที่ทำให้ก๊วนอยู่ได้ |
| คู่ขา | ชนะด้วยกัน 3 ครั้งขึ้นไป | กันคู่ที่บังเอิญชนะครั้งเดียว |

คนที่ยังไม่ครบเกณฑ์แสดงแยกท้ายตารางพร้อมบอกว่าขาดอีกกี่เกม ไม่ใช่ซ่อนทิ้ง

### 7.4 ซีซั่น

- ปิดซีซั่น = ใส่ `ended_at` แล้วเปิดอันใหม่ ข้อมูลเก่าไม่ถูกแตะ
- ELO เริ่มใหม่ที่ 1000 ทุกซีซั่น
- ดูย้อนหลังได้ทุกซีซั่น

## 8. คนที่หายไปนาน

**เส้น 90 วันนับจาก `last_seen_on`** (วันที่เช็กชื่อล่าสุด ไม่ใช่วันที่ลงเล่นล่าสุด — มาแล้วนั่งดูก็นับว่ามา)

กฎ 4 ข้อ

1. **ไม่มีปุ่มลบทั้งระบบ** มีแต่ `archived_at` — `match_players` อ้างถึงเขาอยู่
   (ของเดิมมีบั๊กนี้จริง: reset ผู้เล่นแล้วประวัติเหลือแต่รหัส)
2. **ระบบชี้ให้ดู หัวก๊วนกดเอง ไม่เก็บอัตโนมัติ** — ก๊วนหยุดหน้าฝนหรือปิดเทอม คนหายพร้อมกันทั้งก๊วน อัตโนมัติจะกวาดเรียบในวันเดียว
3. อยู่ในกรุ = ไม่ขึ้นหน้าเช็กชื่อ ไม่ขึ้นกระดานอันดับ แต่สถิติและประวัติยังครบ
4. โผล่มาเช็กชื่อเมื่อไหร่ ระบบเอาออกจากกรุให้อัตโนมัติ ไม่ต้องกดคืน

## 9. คนที่อยู่หลายก๊วน

**ไม่มีเรตเฉลี่ยรวมทุกก๊วน** เพราะ ELO วัดว่าเก่งกว่าคนในก๊วนนั้นแค่ไหน ไม่ได้วัดว่าเก่งแค่ไหน
คนที่ได้ 1200 ในก๊วนมือ N กับคนที่ได้ 1000 ในก๊วนมือ B เอามาเฉลี่ยแล้วไม่ตรงกับความจริงสักด้าน
จะเฉลี่ยได้ต่อเมื่อสองก๊วนเคยแข่งข้ามกันมากพอจนคาลิเบรตกันได้ ซึ่งไม่ใช่กรณีนี้

| รวมข้ามก๊วนได้ | รวมไม่ได้ |
|---|---|
| จำนวนเกมที่ลง | เรตเฉลี่ย |
| ชนะรวม แพ้รวม | มือเฉลี่ย |
| จำนวนครั้งที่ไปตี | อันดับรวม |
| รายชื่อก๊วนที่อยู่ | อัตราชนะรวม |

หน้าโปรไฟล์แสดงการ์ดแยกก๊วนละใบ (เรต มือ อันดับในก๊วนนั้น) กับแถบสรุปที่รวมได้จริงด้านบน
รวมได้เฉพาะคนที่ผูกบัญชีแล้ว

## 10. เงินและหน้าสรุปสาธารณะ

1. หัวก๊วนกรอก: ชั่วโมง, ค่าสนามต่อชั่วโมง, จำนวนสนาม, ลูกที่ใช้, ราคาต่อกล่อง
2. **คนหารตั้งต้นจากคนที่เช็กชื่อ session นั้น** ไม่ใช่สมาชิกทุกคนในก๊วน (ของเดิมเป็นบั๊ก)
3. ปรับรายคน: เต็ม / ครึ่ง / ไม่จ่าย
4. กดเผยแพร่ → ได้ `share_token` 128-bit → ลิงก์ `/s/<token>`

**สูตรค่าลูกใช้อันเดียวทั้งระบบ**: `ลูกที่ใช้ × (ราคากล่อง ÷ 12)` เศษได้
ของเดิมหน้าสต๊อกปัดขึ้นเป็นกล่อง หน้าคิดเงินคิดเป็นเศษ ได้เลขคนละตัวจากข้อมูลเดียวกัน

**หน้า `/s/<token>`** แสดงแค่: วันที่, ค่าสนาม, ค่าลูก, รวม, ตารางคนละเท่าไหร่, เวลาอัปเดตล่าสุด
ไม่มีอันดับ ไม่มีรายชื่อคนที่ไม่ได้จ่าย ไม่มีปุ่มแก้อะไร เปิดได้โดยไม่ต้องล็อกอิน
หัวก๊วนกด revoke token ได้ถ้าส่งผิดกลุ่ม

## 11. การทำงานตอนไม่มีเน็ต

| เขียนอะไร | offline ได้ | กันเขียนซ้ำด้วย |
|---|---|---|
| เช็กชื่อ | ได้ | PK (session, player) |
| ยืนยันคิวลงสนาม | ได้ | `matches.client_id` |
| บันทึกทีมชนะ | ได้ | update ค่าเดิม เป็น idempotent อยู่แล้ว |
| ตัดสต๊อกลูก | ได้ | `stock_movements.client_id` |
| กรอกเงิน (ยังไม่เผยแพร่) | ได้ | 1 settlement ต่อ session |
| เผยแพร่สรุป | ไม่ได้ | ต้องขอ token จากเซิร์ฟเวอร์ |
| จัดการสมาชิก / จัดการก๊วน | ไม่ได้ | ต้องผ่าน RLS |

- คิวงานอยู่ใน IndexedDB ส่งตามลำดับที่กดเมื่อเน็ตกลับมา
- ทุก op มี `client_id` ที่ client สร้างเอง ส่งซ้ำกี่รอบก็ได้แถวเดียว
- อัลกอริทึมจัดคิวเป็น pure function ทำงานบน snapshot ที่ cache ไว้ ไม่ต้องพึ่งเซิร์ฟเวอร์
- UI ต้องแสดง "ค้างส่ง N รายการ" ไม่ใช่หมุนค้าง

## 12. บั๊กของเดิมที่ spec นี้ปิดไปด้วย

| บั๊ก | ปิดด้วย |
|---|---|
| ELO เพี้ยนเพราะ matchHistory cap 50 | matches เป็น append-only คำนวณตอนอ่าน |
| ตัวกรองประวัติ "อิสระ" ว่างตลอด เพราะไม่เคยบันทึกโหมด | `queue_mode` บนแถว match |
| ทีม RR ไม่สมดุล (เก่งจับกลาง) | คิดครบทั้ง 3 แบบที่สี่คนแบ่งได้ |
| "สุ่มคู่ใหม่" บอกว่ายกเลิกผล แต่ไม่ยกเลิกจริง | ไม่มีการสุ่มทั้งรอบแล้ว |
| reset ผู้เล่นแล้วประวัติเหลือแต่รหัส | ห้ามลบผู้เล่น มีแต่ archive |
| คนหารตั้งต้นเป็นสมาชิกทุกคน | ตั้งต้นจากคนที่เช็กชื่อ |
| สูตรค่าลูกไม่ตรงกัน 2 ที่ | สูตรเดียวทั้งระบบ |
| `save()` กลืน error เงียบ ข้อมูลหายโดยไม่รู้ตัว | คิว offline แสดงจำนวนค้างส่งเสมอ |
| state UI ไม่ถูกกู้คืนตอน reload | state อยู่ที่เซิร์ฟเวอร์ |
| ชื่อผู้เล่นไม่ถูก escape ในปุ่มบันทึกผล | React escape ให้เป็นค่าเริ่มต้น |

## 13. ข้อสมมติที่รอยืนยันจากเพื่อน

ทั้งหมดมีค่าเริ่มต้นแล้ว สร้างต่อได้เลย ถ้า feedback ต่างค่อยปรับ

| # | ข้อสมมติ | ค่าที่ใช้ไปก่อน |
|---|---|---|
| 1 | สองเครื่องกรอกผลสนามเดียวกันตอนเน็ตหลุด | ผลที่ถึงเซิร์ฟเวอร์ก่อนชนะ อีกฝั่งเห็นข้อความว่าถูกบันทึกไปแล้ว |
| 2 | เศษบาทจากการหาร | ปัดขึ้นทุกคน ส่วนเกินเข้ากองกลางก๊วน |
| 3 | โหมด "ผสม" คุ้มที่จะเก็บไว้ไหม | เก็บไว้ก่อน ถ้าไม่มีใครใช้ค่อยตัด |
| 4 | จำนวนคนที่ไปตีหลายก๊วนจริง | ทำหน้าโปรไฟล์รวมไว้ ถ้าแทบไม่มีใครค่อยเลื่อนออก |
| 5 | เส้น 90 วัน | 90 วัน ปรับได้จากหน้าตั้งค่าก๊วน |
| 6 | ความยาวซีซั่น | หัวก๊วนกดปิดเอง ไม่บังคับความยาว |

## 14. ลำดับที่จะสร้าง

1. **ฐาน** — โปรเจกต์ Next.js, Supabase, schema, RLS, seed ก๊วนแรก
2. **ตัวตน** — ล็อกอิน, บทบาท, จัดการสมาชิก, ลิงก์เชิญผูกบัญชี
3. **โหมดสนาม** — session, เช็กชื่อ, เครื่องจัดคิว, บันทึกผล *(มี unit test ของอัลกอริทึมจัดคิวเป็นเงื่อนไขผ่าน)*
4. **ออฟไลน์** — outbox, client_id, PWA
5. **อันดับ** — `season_standings`, 4 กระดาน, ระดับมือ, ซีซั่น
6. **เงิน** — กรอก, เผยแพร่, หน้า `/s/<token>`
7. **ดูแลระยะยาว** — คนหายนาน, โปรไฟล์ข้ามก๊วน, สต๊อกลูก

ข้อ 1 ถึง 3 คือชุดที่ใช้งานจริงได้ชุดแรก ข้อ 4 ต้องมาก่อนเอาไปใช้หน้าสนามจริง
